## 一、总览：77 张表的职责地图

v4 共 77 张表。对考试业务开发来说，只需关注 **32 张考试业务表**（其余 45 张是 Smart Admin 框架自带，按原有方式使用即可）。

考试业务 32 张表按"写数据的入口"分组如下：

```
用户操作           →  写入的表                     →  读取的表（展示用）
══════════════════════════════════════════════════════════════════════
教师上传语料       →  t_corpus                    →  t_corpus
教师管理题库       →  t_question                  →  t_question
教师创建考试       →  t_exam, t_exam_question      →  t_exam, t_exam_question
教师发布考试       →  t_paper_snapshot             →  t_paper_snapshot（存档）
教师配置评分标准   →  t_scoring_rubric             →  t_scoring_rubric

学生身份验证       →  t_exam_verification          →  t_exam_verification
学生答题（提交）   →  t_student_answer             →  t_student_answer
                    →  t_answer_detail
学生答题（草稿）   →  t_answer_detail.draft       →  —
学生选课           →  t_course_selection           →  t_course_selection
                    →  t_enrollment_log            →  t_enrollment_log（审计）

AI 评分回调        →  t_answer_detail（更新评分）  →  —
教师复核成绩       →  t_answer_detail（调整分数）  →  t_score_report（重新生成）
成绩汇总发布       →  t_score（原始总分）          →  t_score_report（前端展示）
                    →  t_score_report

学生申请复议       →  t_appeal, t_attachment       →  t_appeal
学生请假           →  t_leave_application          →  t_leave_application
                    →  t_attachment
学生申请奖励       →  t_reward_application         →  t_reward_application
                    →  t_attachment

客户端上报异常事件 →  **t_monitor_event**           →  t_monitor_event
教师/系统判定      →  **t_abnormal_decision**       →  t_abnormal_decision
```

## 二、异常监控体系：t_monitor_event + t_abnormal_decision

v4 中 `t_abnormal_behavior` 已删除，异常监控统一使用新体系：

| 表 | 职责 |
|---|------|
| `t_monitor_event` | **记录事件**（发生了什么）：event_type, severity, description, evidence_url, occurred_at, received_at |
| `t_abnormal_decision` | **记录判定**（怎么处理）：decision, deduct_points, comment, version（初判→复核→改判） |

### 为什么比旧表好？

| 旧表 t_abnormal_behavior（已删除）的缺陷 | 新体系的改进 |
|---|---|
| 事件与判定混在同一行 | 分离，一个事件可有多个判定（初判→复核→改判） |
| 改判靠 UPDATE 覆盖，无法追溯 | `t_abnormal_decision.version` 保存每次判定版本 |
| 字段臃肿 | 事件只记"发生了什么"，判定只记"怎么处理" |
| 无客户端/服务器双时间戳 | `occurred_at` + `received_at`，可检测时间篡改 |

### 代码写法

```
1. INSERT INTO t_monitor_event (...) VALUES (...)   -- 记录事件
2. INSERT INTO t_abnormal_decision (...) VALUES (...) -- 记录判定
```

## 三、成对出现的表：职责分离说明

v4 中有三组"一对多"的表设计，容易混淆，这里说清各自边界：

### 3.1 成绩：t_score ↔ t_score_report

| | t_score | t_score_report |
|---|---|---|
| **定位** | 权威原始总分 | 展示用报告 |
| **谁来写** | 批改完成后一次性写入 | 报告生成时写入，可覆盖更新 |
| **内容** | exam_id, student_id, total_score, rank_position | display_score, question_scores(JSON), three_dimension_avg(JSON), overall_suggestion, model_trace_id |
| **关系** | 1:1（score_id = report.score_id） | — |
| **前端读哪张** | — | **S-07 成绩详情页 → t_score_report** |
| **后端算排名** | 从 t_score 算 | — |

> 💡 **一句话**：t_score 是"数据库里的成绩单"，t_score_report 是"发给学生的成绩单"。

### 3.2 异常监控：t_monitor_event ↔ t_abnormal_decision

| | t_monitor_event | t_abnormal_decision |
|---|---|---|
| **定位** | 事件事实 | 判定结论 |
| **谁来写** | 客户端自动上报 | 系统自动判定 / 教师手动判定 |
| **内容** | event_type, severity, description, evidence_url, occurred_at, received_at | decision, deduct_points, comment, version |
| **关系** | 1:N（一个事件可有多个判定） | — |
| **改判如何体现** | 不改 | INSERT 新行，version+1 |

> 💡 **一句话**：event = "学生切屏 15 秒"，decision = "系统判定违规扣 2 分 → 教师复核改为误判不扣分"。

### 3.3 附件：evidence_urls（JSON 字段） ↔ t_attachment（独立表）

| | evidence_urls (JSON) | t_attachment |
|---|---|---|
| **适用场景** | 少量图片（≤3 张），不需要独立管理 | 需要独立管理、分类查询的附件 |
| **所在表** | t_appeal, t_leave_application, t_reward_application | 独立表，通过 biz_type + biz_id 关联 |
| **何时用哪个** | 业务申请时随手传的截图 | 需要附件列表、排序、按类型检索 |
| **关系** | evidence_urls 存 URL 数组，t_attachment 存文件元数据 | 两者可共存，不互斥 |

> 💡 **一句话**：evidence_urls 是"快捷通道"（简单场景直接用），t_attachment 是"正式通道"（需要附件管理功能时用）。

## 四、开发速查：常见场景 → 该写哪张表

| 场景 | 写入的表 | 注意事项 |
|------|----------|----------|
| 学生切屏 | `t_monitor_event` | — |
| 系统自动判定切屏为违规 | `t_abnormal_decision` | event_id 关联上面的 event |
| 教师复核改为误判 | `t_abnormal_decision`（INSERT 新行） | version=2，不要 UPDATE 旧行 |
| 学生答完一题 | `t_answer_detail.user_answer` 写入 | 草稿走 draft 字段 |
| 自动保存草稿 | `t_answer_detail.draft` 写入 | 每 30 秒一次，带 answer_version 乐观锁 |
| AI 评分回调 | `t_answer_detail` 更新评分字段 | relevance_score / knowledge_coverage / logic_expression / weighted_score / final_score / ai_feedback |
| 教师批改完成 | `t_score`（INSERT）+ `t_score_report`（INSERT） | 先写 t_score，拿到 score_id 再写 t_score_report |
| 学生上传复议证据 | `t_attachment`（biz_type=1） | 也更新 t_appeal.evidence_urls |
| 考试发布 | `t_paper_snapshot`（INSERT） | 整卷 JSON 存档，此后题库变更不影响本次考试 |
| 学生验证身份 | `t_exam_verification`（INSERT/UPSERT） | 失败累计 failed_times，达标后 locked_until |
| 选课 | `t_course_selection`（INSERT）+ `t_enrollment_log`（INSERT, operation=1） | 两表同时写 |
| 退课 | `t_course_selection`（deleted_flag=1）+ `t_enrollment_log`（INSERT, operation=2） | — |
